DockAnalyzer — User Guide

Follow the essential steps to run DockAnalyzer in UCSF ChimeraX and understand the files generated by the analysis.

Running DockAnalyzer

DockAnalyzer identifies the receptor and docking poses from the ChimeraX model IDs. For this reason, the structures must be opened in the correct order before running the analysis.

1

Download and Extract

Download the DockAnalyzer package and extract the ZIP archive while preserving its original directory structure.

2

Open UCSF ChimeraX

Start UCSF ChimeraX before loading the receptor, ligand poses, or the DockAnalyzer analysis script.

3

Open the Receptor First — It Must Be Model #1

Open the prepared receptor or target protein before any ligand pose. DockAnalyzer reserves ChimeraX model #1 for the receptor. Model #1 is therefore not treated as a docking pose.

4

Open All Ligand Poses After the Receptor

Open each ligand pose as an individual structure in the same ChimeraX session. Models loaded after the receptor — normally #2, #3, #4, and so on — are considered poses to be analyzed.

5

Verify the Model IDs

Before running DockAnalyzer, confirm that the target protein is model #1 and that every intended ligand pose is loaded as a separate subsequent model. If the receptor is not #1, restart or reorganize the ChimeraX session before analysis.

6

Run dockanalyzer_runscript.py

In the ChimeraX command line, run the dockanalyzer_runscript.py file using the runscript command followed by the full path to the file. For example: runscript "C:\path\to\DockAnalyzer\dockanalyzer_runscript.py". DockAnalyzer will then analyze the loaded poses against receptor model #1.

7

Automatic Output Folder

Results are automatically saved to DockAnalyzer_Output on the user's Desktop. If this folder does not already exist, DockAnalyzer creates it automatically. Generated files are organized into subfolders according to file type or extension, such as CSV, Excel, JSON, Reports, Images, and Logs.

8

Choose Whether to Generate Pose Snapshots

At the end of the workflow, DockAnalyzer asks whether a snapshot should be generated for each analyzed pose. If enabled, snapshots are produced in ranking order and saved in the Images output folder using rank-first names, for example rank1_pose_2.png, rank2_pose_4.png, and rank3_pose_3.png.

9

Choose Whether to Generate Performance Data

DockAnalyzer also asks whether performance information should be generated. When enabled, these outputs record how long the analysis and individual processing stages required, allowing the runtime of the workflow to be evaluated.

Critical model-ID rule: the receptor must be loaded first and must be ChimeraX model #1. All models loaded after it are interpreted as docking poses for analysis.

When a docking output contains multiple poses in a single .pdbqt file, use the Splitting Poses Code before loading the poses into ChimeraX.

Generated Results

DockAnalyzer generates complementary outputs for scientific interpretation, detailed inspection, reproducibility, and performance evaluation. The most important file for routine interpretation is the Scientific Summary workbook.

Primary result

Scientific Summary — Excel Workbook

The file dockanalyzer_<timestamp>_scientific_summary.xlsx provides the consolidated scientific summary of the analysis. It brings together the key information generated for the analyzed poses in a compact spreadsheet, making it the main output to consult when reviewing and comparing DockAnalyzer results. It is saved in the Excel subfolder.

Execution log and run summary Execution messages, stage information, diagnostics, and run-level metadata useful for validation and troubleshooting. .log / .json — Logs / JSON

Where to start: for routine scientific interpretation, open the *_scientific_summary.xlsx file first. The other outputs provide more detailed, machine-readable, visual, or diagnostic information when needed.

Important Notes

  • Model #1 is reserved for the receptor. Do not load a ligand pose before the target protein.
  • Each docking pose should be loaded as an individual ChimeraX model after the receptor. If necessary, see the Pose Splitting Code .
  • The output destination is automatic: Desktop/DockAnalyzer_Output. The directory is created when absent and files are separated into type-based subfolders.
  • The *_scientific_summary.xlsx workbook is the main consolidated scientific result and should normally be reviewed before the more detailed exports.
  • Pose snapshots and performance timing data are optional and are selected through questions presented at the end of the workflow.
